# 期货程序化交易系统试运行实盘验收清单

> 本清单用于在券商测试/仿真环境完成试运行闭环的人工验收。最终结论必须与系统导出的 DOCX 报告结论一致，并保留截图、日志与委托/成交编号作为证据。

## 零、启动系统

- [ ] 启动后端（推荐先启动后端再启动前端）：

```powershell
cd D:\quant\back_end
..\.venv\Scripts\python.exe -m uvicorn src.api:app --host 127.0.0.1 --port 8000
```

- [ ] 启动前端：

```powershell
cd D:\quant\front_end
npm.cmd run dev
```

- [ ] 打开浏览器访问前端地址，进入“试运行操作台”。

## 一、测试前准备

- [ ] 确认账户已通过券商测试/仿真柜台验证，`config_production.json` 中 `environment` 与登录环境一致。
- [ ] 确认 `trial_run.allowed_symbol`、`strategy.symbol`、`risk.allowed_symbols[0]` 为同一个可交易合约。
- [ ] 确认合约当前处于交易时段，行情前置能推送目标合约 tick。
- [ ] 确认账户目标合约真实持仓为 0，且无活动委托。
- [ ] 记录：测试时间、账号掩码、环境、合约、行情前置、交易前置。

## 二、真实报单链路验收

- [ ] 登录后进入 `/trial-run`，点击“开始试运行”。
- [ ] 在有效 tick 到达后 5 秒内看到 `tick_count >= 1`、`bar_count = 1`。
- [ ] 页面显示 1 笔开仓委托，方向为“多”、开平为“开仓”、数量为 1，委托时间完整。
- [ ] 记录真实委托号：________。
- [ ] 若 2 秒内未成交，观察“自动撤单重报/追价”，确认每次重报前已收到券商撤单确认。
- [ ] 确认任一滚动分钟内真实报单数不超过 5，且始终为平仓保留至少 1 个名额。
- [ ] 若真实成交：记录成交号，等待首根成交后 Bar 或 75 秒看门狗生成平仓委托，并确认券商持仓最终归零。
- [ ] 若未真实成交：按第三节执行模拟轨道验收。

## 三、无对手盘模拟成交验收

- [ ] 真实委托已报未成超过 2 秒后，点击“撤单并准备模拟验证”。
- [ ] 确认券商侧真实委托已撤，页面进入“等待券商撤单确认”。
- [ ] 等待页面显示“可模拟开仓”且模拟账本绑定当前真实源订单。
- [ ] 点击“模拟开仓成交”，确认弹窗展示委托号、合约、多/空、开/平、价格、数量，并明确提示“不是券商真实成交”。
- [ ] 记录模拟开仓委托号：________。
- [ ] 等待模拟平仓委托生成，点击“模拟平仓成交”。
- [ ] 确认页面结论为“真实报单链路通过；成交后处理由模拟成交验证”，券商真实持仓保持 0。
- [ ] 导出 DOCX 报告，确认报告明确说明成交为模拟，未出现“真实成交通过”。

## 四、失败与恢复路径验收

- [ ] 无 tick 15 秒：页面显示“未收到目标合约 tick”及订阅/最近行情诊断，不再无限递增等待。
- [ ] 行情过期：追价或平仓看门狗按后端规则失败并保留证据。
- [ ] 撤单失败：页面给出失败原因，不自动重报。
- [ ] 风控限频不足：准备阶段被拒绝并显示剩余额度。
- [ ] 真实持仓未归零时停止/重置/注销：返回 `flatten_required`，保留会话、引擎与订单证据。
- [ ] 急停：持仓与活动委托被冻结，人工平仓归零后停止仍标记为失败且 `success_basis=manual_flatten_after_trial_failure`。
- [ ] 页面刷新：从后端恢复当前试运行状态，不重复报单。
- [ ] 后端重启：非终态运行标记 `aborted/backend_restarted`，重新准备前先检查恢复合约的券商持仓。

## 五、通过标准

- `passed_real`：真实开仓成交、真实平仓成交、券商持仓归零、无活动委托、对账一致。
- `passed_simulated`：至少一笔真实委托被券商接受；真实委托已撤且真实持仓为 0；模拟开仓与平仓完成；模拟持仓归零；报告如实说明。
- `failed` / `aborted`：必须保留人工处置证据，不能作为通过结论。
