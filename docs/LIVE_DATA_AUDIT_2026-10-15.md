# 柜台数据来源与账户指标核验（2026-10-15）

## 核验范围

使用本机原生 vn.py/CTP 服务和用户自行完成的网页登录，只读核对账户、行情、保证金与页面数据。没有发送实盘订单、撤单或启动策略。运行日志和账户原始回报留在仓库外；本文不保存账号、金额、密码或认证码。

生产版 API 库不等于柜台环境认证：本文确认数据来自配置的柜台连接，不据此证明柜台属于真实资金环境，也不独立认证交易所价格。

## 来源核对

| 数据 | 观察与结论 |
| --- | --- |
| 账户 | MD、TD、结算、合约、账户、持仓就绪。新版 dashboard 的余额、可用、保证金、手续费、持仓盈亏、持仓加平仓盈亏与 reconcile 中柜台账户回报逐项精确到分一致。 |
| 黄金 Tick | `au2612` 收到 `source=vnpy` 的连续回报，例如 14:54:14、14:54:52.5、14:54:53.5（Asia/Shanghai）。价格与盘口随回报变化，未使用本地随机行情。柜台未给出买价时页面显示未知。 |
| 保证金 | `status=ready`、`margin_source=ctp_query`、交易日 `20261015`，黄金多空比例均为 7%，按手固定金额为 0。这是当前连接账户的查询结果，不是通用交易所保证金建议。 |
| 历史 K 线 | 本地 `quotes.db` 的 bars 表为 0 行；K 线接口返回空列表、`data_source=missing`。尚无导入的历史行情。订阅后的 Tick 聚合不能补齐完整历史。 |
| 委托与持仓 | 核验时活动委托、持仓和未决意图均为 0；这不能作为下单、撤单或完整柜台对账已验收的证据。 |
| 测试图片 | E2E 图片中的账户和行情是明确标注的隔离样本，不属于实盘证据，也没有写入实盘历史库。 |

## 本次修复

1. 账户未就绪、字段缺失、非有限金额或断线时，账户指标返回 `null`，页面显示“—”；有效的柜台 0 不再被策略盈亏覆盖。WebSocket 断开清空旧金额。
2. 移除账户指标中的默认百万本金。旧的 `return_rate`、`today_return` 和 `initial_capital` 保留兼容字段但返回 `null`。缺少日终基准和出入金数据时不显示投资收益率。
3. “浮动盈亏”使用柜台持仓盈亏。持仓加平仓盈亏单独列示并注明未扣手续费。会话权益变动以首次有效会话快照为基准，注明未剔除出入金；风控自己的日基准不受影响。
4. 名义敞口按 `abs(手数) × 开仓均价 × 合约乘数` 计算；乘数或成本缺失则未知。使用真实合约代码，不使用内部的“合约_方向”键。表格和环图标为成本名义金额，不再冒充保证金。
5. 权益曲线改画柜台余额，未知/非有限数据不进入曲线或权益日志。样本不足的回撤为未知，窗口回撤明确包含出入金影响。图表使用已注册的 Canvas renderer，并测试已知和未知状态。

6. 行情页保留柜台提供的来源和完整时间戳，显示距行情时间，不将浏览器收到推送的时间当作行情时间。历史缺失明确提示，Tick 增量不冒充完整历史；合约目录不标为成交量热门排名。

## 仍然存在的边界

没有接入历史行情供应商、完整交易日历、出入金及日终权益分析。持续跨日/故障恢复、真实成交回报、实盘下单和撤单尚未验收。账户就绪依赖现有网关快照门禁，页面更新时间是推送时间，不是每个柜台字段的独立采集时间。
