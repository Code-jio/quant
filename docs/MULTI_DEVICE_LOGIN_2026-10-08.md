# 同一账户多浏览器登录

用户使用场景为同一电脑的不同浏览器。本次不更改监听地址、防火墙或网络部署，继续使用同一个 `http://127.0.0.1:5174/` 入口。

## 行为

| 操作 | 新行为 |
|---|---|
| 第一端输入账号、密码 | 通过柜台登录，创建唯一 CTP 引擎及该浏览器会话 |
| 另一浏览器输入相同账号、密码和连接配置 | 验证密码，发放独立 Cookie，复用当前引擎；不重新连接柜台或重置风控/策略/账本 |
| 同浏览器新标签或刷新 | 通过现有 HttpOnly Cookie 恢复登录，不再次登录柜台 |
| 账户会话 → 退出当前端 | 仅撤销该浏览器会话；同一浏览器共享 Cookie 的标签页也失效，其他浏览器保持在线 |
| 最后一端退出当前端 | 后台账户、策略仍运行；随后可重新输入密码加入 |
| 账户会话 → 断开全部终端 | 明确确认后断开账户、停止后台引擎，全部会话失效；不会自动撤销柜台已有委托 |
| 不同账号或连接配置的新终端 | 拒绝加入，保持当前连接 |
| 同一端重复登录 | 只轮换自身 Cookie，不撤销其他端 |

这是单一账户、多会话的共享执行器。各端具有相同交易权限，共享委托、持仓、策略、风控和急停状态；不是多账户并行服务。自选、图表与界面配置仍保存在各浏览器本地，不自动跨浏览器同步。

## 接口及安全边界

- 新增 `POST /auth/session/logout`，只注销当前令牌。既有 `POST /auth/logout` 保持全局断开语义，以兼容旧客户端。前端不会在单端退出接口失败时退回全局退出。
- `POST /auth/login` 返回 `connection_reused`；`GET /auth/status` 返回 `multi_device_supported` 和当前账户会话数。匿名状态仍不返回账户、日志或真实会话数量。
- 首次成功柜台登录后，只为新增的多端校验保存内存中的随机盐与密码派生校验值；不将密码或校验值写入配置、数据库、响应或日志。使用 32 字节随机盐、PBKDF2-HMAC-SHA256 的 600000 轮及恒定时间比较；绑定账号、经纪商、前置、环境、AppID 和认证配置。
- 校验基于当前连接最近一次成功柜台登录所用密码，不对每个浏览器重复请求柜台登录。在外部修改交易密码后，应断开全部并重新登录以刷新此校验值。全局断开、切换账户、服务退出会清除校验值。
- 每个来源地址 60 秒内 5 次登录参数/认证拒绝后限制继续尝试，并返回 `Retry-After`；同机浏览器经过本机代理时共享此限制。正常已登录访问不受该登录限制影响。最多 32 个有效会话，单个会话有效期沿用 24 小时。
- 未认证的加入请求不能修改风险参数或启动策略。现有已授权 API 客户端显式修改连接配置、风险参数或启动策略的重新登录，仍属于全局账户切换，会撤销旧会话；普通登录页面不会发送这些运行参数。
- 登录参数错误响应不回显密码。WebSocket 在等待消息后再次验证会话，推送前也检查有效性，防止退出后继续使用旧连接。正常 ASGI 连接取消会清理子任务及连接记录。

密码校验实现参考 [Python hashlib 文档](https://docs.python.org/3/library/hashlib.html#hashlib.pbkdf2_hmac)及 [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)。本功能没有新增外网入口或分级交易权限。
