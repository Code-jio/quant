## 实现范围

1. 原生 `ReqQryInstrumentMarginRate` 查询当前账户投机保证金，保存多空比例和按手金额。若 `IsRelative=1`，再查询交易所基准并逐字段相加。只接受已确认的单腿期货合约；期权、组合以及组合优惠不在本次范围内。
2. 请求按网关计时器限速，最多一笔保证金查询在途；账户/持仓刷新使用独立计时，避免多合约保证金队列令快照过期。通过请求号、查询阶段、合约、投机标志和响应中的身份字段核对结果，收到最后一包才生效。空结果、多条结果、无效字段、发送失败、柜台错误或超时保持未知。
3. 按账户会话保存查询结果。交易连接断开或交易日变化时清除柜台值；30 分钟到期后清除旧值并排队刷新。已配置的人工核实比例仅是查询成功前的备用值；不会在已学到的柜台值失效后恢复旧配置。
4. 风控和策略手数同时计入按比例与按手金额。活动开仓委托也预留保证金；其元数据未知时阻止新增开仓。保守取多空各字段较大值，可能高于特定方向的实际要求；不计算组合抵扣。
5. 登录后查询接口返回 pending、ready 或 error；公开合约搜索无论是否带 Cookie 都过滤保证金字段，避免账户切换期间锁外身份快照与新账户数据混用。交易面板显示多空比例、按手金额和交易日，切换合约立即清空旧结果，迟到响应不能覆盖新合约。
6. 下单和批量撤单提示改为“请求已发送，请核对柜台回报”，避免把本地发送成功等同于柜台受理或撤单完成。

原生兼容性验证还发现：新接入的保证金回调是 pybind 虚方法，包装时调用保存的原生基类方法会再次进入覆盖回调。本实现直接设置这两项回调，不调用其基类方法，隔离原生测试与实际查询均已通过。

接口语义参考：[CTP 开发者指南的保证金查询说明](https://github.com/ctp-api/CTP-Quantitative-Trading/blob/main/CTP%20Client%20Development%20Guide.md)及[上期技术 Mini API 文档](https://www.simnow.com.cn/DocumentDown/api_3/5_2_4/CTPIIMini_API_Ver1.2.pdf)。具体账户适用值以柜台返回为依据。
