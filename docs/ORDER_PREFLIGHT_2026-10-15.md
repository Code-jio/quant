# 下单前检查与实盘风控加固

本轮根据“实盘运行可靠性与风控”优先级完成一个可独立验收的改造。没有登录真实账户、发送真实报单/撤单或重启用户服务。所有测试使用 FakeGateway 或浏览器拦截样本。

## 行为变化

| 环节 | 原问题 | 现在的行为 |
|---|---|---|
| 下单预览 | 风控、保证金与执行状态分散，发送后才得到拒绝原因 | 委托面板提供可展开的检查区，展示各组阻断项及资金估算；未知值显示“未知” |
| 确认与发送 | 确认框显示旧值，实际发送时重新读取可变表单 | 固定合约、方向、开平、价格、手数和类型；确认期间禁止重复点击 |
| 快捷平仓 | 确认具体手数，却以 `volume=0` 提交全部平仓 | 按确认时的明确手数、开平和报价提交；持仓随后增多不会扩大数量，减少则后端拒绝超量 |
| 本地拒单 | 原生网关价位或最小数量校验发生在创建执行意图之后 | 先执行网关只读校验，本地拒绝不生成未决意图、不误触发“结果未知”急停；真实发送异常仍保持原保护 |
| 行情新鲜度 | NaN、无穷大、未来时间可能被归零为新鲜行情 | 时效校验启用时拒绝异常时间及超过 5 秒容差的未来时间 |
| 保证金 | 依赖定时刷新清除旧柜台值 | 预检查与发送同时验证柜台交易日和 30 分钟有效期；缺失、跨日、过期或明显未来时间均不能用于开仓 |
| 连接 | 引擎自身状态可能仍标记交易中 | 检查实际网关连接状态，网关断开不能因引擎旧状态放行 |

## 接口和数据语义

受保护的 `POST /orders/preflight` 与 `POST /orders` 共用参数解析，返回 `allowed`、`snapshot_only`、`checked_at`、`trading_day`、`checks`、`margin`、`close_available` 和规范化的 `order`。

`checks` 按连接、快照、参数、合约、保证金、执行记录、风控分组。组间可同时报告失败；风控组保留既有规则的首个拒绝原因。预检查不调用柜台、不修改交易日基线、原始风控对象或上次拒单原因、不写入执行意图。频率与重复信号校验作用于副本；只有实际成功发送才记录报单次数。

资金估算沿用现有保守算法：价格 × 合约乘数 × 保证金率 + 按手金额，再乘手数；比例和按手金额分别取多空较高值。`reserved` 为活跃开仓单未成交数量的估算，`remaining = available - required - reserved`。柜台可用资金可能已经扣除部分冻结，因此这里可能重复预留；这是上限保护，不能解释为柜台精确资金预测。平仓不计算新增开仓保证金，可平量按方向、今昨、冻结和活跃平仓委托校验。

检查通过只代表一个时点的本地快照。确认后若发生急停、断连、资金下降或其他状态变化，实际发送会重新检查并拒绝。无法确认发送结果时仍保留未决意图并急停，不自动重报或清除待核对记录。

## 验证

完整回归：后端 **247 项**、前端单测 **29 项**、浏览器 **22 项**通过；Ruff、mypy（41 文件）、ESLint、vue-tsc、生产构建和包体预算通过。

具体命令及测试输出保存在 [验证证据](evidence/order-preflight-20261015/README.md)。新增后端测试覆盖只读副作用、保证金预留、状态变化、断连、未决意图、今昨平仓、非法价位/数量单位、保证金有效期和异常时间。新增浏览器测试覆盖阻断/网络失败、固定确认参数、迟到响应隔离及快捷平仓数量与开平锁定。

页面在 2560×1440、1920×1080、1366×768 和窄屏回归。检查详情默认收起，不占用首屏下单位置；宽屏可展开查看估算。截图中的 E2E_ONLY / E2E2026、价格和资金均为隔离测试数据。

## 加载与剩余边界

- 本轮没有操作实盘进程。后端代码不是热加载；需要用户在合适时机重启后端并刷新前端，之后重新登录。未加载此接口的旧后端会让新前端显示“检查不可用”并阻止发送。
- 真实 Tick 连续性、断线重连、报单与撤单回报仍需专项人工验收；离线测试不证明柜台成交。
- 本地执行记录检查不是全量柜台订单对账。完整对账恢复、未知意图人工处置流程、跨交易日运行和多品种压力测试仍是后续重点；本轮不增加自动清除、自动重报或自动平仓入口。
- 离线验收后，用户已授权自主提交推送并启动实盘只读校验；运行状态以后续实盘核验记录为准。
