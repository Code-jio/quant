# 交易可靠性修复与人工恢复

本轮处理 10 项审查发现。所有验证使用隔离账户、FakeGateway 或拦截原生发送函数；没有登录真实账户、发送真实报撤单、启动实盘策略或重启实盘服务。新建 SQLite 表由执行账本初始化时创建，不删除旧表或旧记录。

| 事项 | 改造后的行为 |
|---|---|
| 资金时效 | 资金与持仓分别检查 60 秒时效；资金查询失败立即失效。跨交易日清除两类就绪状态。资金接口提供采集时间，不能用页面推送时间代替。 |
| 日亏损 | 原生账户读取 PreBalance、Deposit、Withdraw，计算 `(PreBalance + Deposit - Withdraw - Balance) / PreBalance`。不再以盘中首次登录余额代替上日权益。字段缺失、非有限值或上日权益不为正时不能通过该风控检查；平仓不受日亏损限额阻挡。该指标是扣除出入金的账户权益变化，包含手续费等账户结算影响，不是策略收益率。 |
| 搜索竞争 | 手动委托选择器只接受当前请求的响应；清空输入、更新查询和组件销毁均使旧响应失效。 |
| 成交量提醒 | 将累计量转成一秒窗口增量，与此前最多 50 个完整窗口比较；至少 5 个窗口后判断。首个不完整窗口、缺失时间、跨日、计数器重置和连接中断不用于放量推断。 |
| 合约状态 | 在 vn.py 丢弃字段前保存 IsTrading、OpenDate、ExpireDate；未知保持未知。原生开仓要求已确认的挂牌状态；到期或明确不可交易的合约不能下单。挂牌核验不证明账户权限。 |
| 委托恢复 | 查询完整的当日委托和成交，按请求编号、交易日和账户隔离；查询失败、超时、断线或新委托/成交回报使快照失效。区分本地快照就绪与本次委托/成交记录核对结果。 |
| 保证金预留 | 保存资金查询发起时间与各委托回报时间；只有后续资金查询明确覆盖该委托时才免除重复预留。发送中、回报顺序不明或委托更新晚于查询时继续保守预留。 |
| 环境标识 | 登录页选择“生产版 API / 测试版 API”，另外提示柜台资金环境待独立核验。经纪商、地址、AppID、认证码读取方式保持原配置优先级。 |
| 合约浏览 | 国内范围过滤后分页，提供完整匹配数量、品种根码筛选及月份/到期信息；每页 60 条。不会把排序称为主力或成交量排名。 |
| 本地条件单 | 持久化条件、移动止损极值、状态和关联委托；发送前保存 triggering。重启后 pending 变为 paused，triggering 变为 unknown；必须人工复核才能重新启用。条件单依赖本地服务和行情，不是柜台托管止损。 |

## 对账与恢复操作

1. 在委托面板打开“对账与恢复”，点击“查询完整柜台快照”。这是受账户会话保护的只读查询，不发送交易委托。
2. 需要修改本地记录时，先点击“暂停交易并核对（保留挂单）”。已有挂单仍由柜台管理；本操作不撤单。
3. 核对柜台委托、成交及本地差异，填写至少 12 个字符的凭证编号或核对依据；同步前有独立确认框。同步不会重放策略成交回调或重建持仓。
4. 对当日未决执行意图，选择参数一致的柜台委托。若柜台确实未收到，必须人工提供核对依据；程序同时要求查询晚于意图至少 30 秒，且当日无同合约委托/成交歧义。仅查询不到不等于未发送。
5. 处置保存在账户隔离的 resolutions 表和审计日志。处置后仍保持急停，操作者另行决定是否解除；不会自动重新报单。
6. 重启恢复的本地条件单需再次复核，启用时恢复对应行情订阅。关联的未知意图确认未发送后，条件单仍暂停；确认已发送后记录关联委托，不再次触发。

快照有效期为 30 秒；两个查询都完成才是完整快照。处理中切换账户、错误请求号、跨日、错误回报和过期快照不能用于处置。历史未决意图、旧版本缺少交易日的意图、缺少关联证据的 unknown 条件单继续保持阻断，需要历史柜台凭证及受审计的维护处置；不能删库绕过。对账不是事后篡改订单状态的工具，不允许将终态回退到活动状态或减少已成交量。

## 接口

- `GET /watch/search`：增加 offset、product；返回 total、paginated、products，仍不公开账户保证金。
- `GET /trading/reconcile`：增加 generation、snapshot_ready、broker_snapshot、differences、pending_intents、conditional_orders；reconciled 仅表示本次新鲜委托/成交快照与本地记录一致。
- `POST /trading/reconcile/query`：查询当日柜台委托/成交。
- `POST /trading/reconcile/import`：人工同步；要求 generation、snapshot_id、note 及急停。
- `POST /trading/reconcile/resolve`：人工处理当日意图；另外要求 intent_id、order_id（明确确认未发送时为空）。
- `POST /trading/conditional/{id}/review`：人工 resume/cancel；要求 generation、action、note。
